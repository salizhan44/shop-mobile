# shop-mobile

Мобильное приложение магазина (Expo, package `com.rola.shop`). Каталог, корзина, заказы, поддержка, пуши по заказам.

API и база — в репозитории [shop-admin](https://github.com/salizhan44/shop-admin) (ветка `dev`). Сначала поднимите сайт и Postgres там.

## Требования

- Node.js 20+
- Android Studio, JDK 17, Android SDK
- Физический Android-телефон в той же Wi‑Fi, что и компьютер (для пушей надёжнее эмулятора)
- Запущенный `shop-admin` (`npm run dev` на порту 3000)

**Expo Go не используйте** для проверки уведомлений: нужен development build (`expo-dev-client`). После смены `google-services.json` приложение пересоберите, не только Metro.

На Windows, если `npx` ругается на политику выполнения, вызывайте `npx.cmd`.

## Первый запуск

```bash
npm install
cp .env.example .env
```

Положите настоящий `google-services.json` из Firebase (Android-приложение с package `com.rola.shop`) в корень `mobile/`. Файл в git не попадает; шаблон — `google-services.json.example`.

Папка `android/` в репозитории не хранится. Первая нативная сборка создаст её сама:

```bash
npx expo run:android
```

Дальше, когда нативка уже стоит на телефоне, достаточно Metro:

```powershell
$env:REACT_NATIVE_PACKAGER_HOSTNAME="192.168.1.10"
npx expo start --dev-client --lan --port 8081
```

Подставьте **свой** IP ноутбука вместо `192.168.1.10`. Телефон и компьютер — в одной Wi‑Fi сети.

В `.env` для телефона:

```
EXPO_PUBLIC_API_URL=http://192.168.1.10:3000
```

На эмуляторе Android API часто `http://10.0.2.2:3000`. В браузере / на том же ПК — `http://localhost:3000` из `.env.example`.

## Вход в приложение (клиент)

Готового аккаунта **нет** — на экране **Регистрация**:

| Поле | Что вводить |
|------|-------------|
| Имя | любое, например `Тест` |
| Email | любой, например `client@local.test` |
| Пароль | **не короче 8 символов**, например `testpass8` |

У поля пароля есть кнопка **Показать / Скрыть**.

Уже есть аккаунт — **Вход** с тем же email и паролем.

**Не используйте** `owner@local.test` — это логин **сотрудника на сайте**, не клиента.

После входа система спросит разрешение на уведомления — согласитесь, иначе пуши не зарегистрируются.

## Вход на сайт (для проверки заказов / поддержки)

См. [README shop-admin](https://github.com/salizhan44/shop-admin/blob/dev/README.md).

Кратко, после seed на сайте:

| Поле | Значение |
|------|----------|
| Email | `owner@local.test` |
| Пароль | `changeme` |

URL: http://localhost:3000 (с телефона — `http://IP-ноутбука:3000`).

## Что есть в приложении

- Нижние вкладки: **Каталог**, **Корзина**, **Мои заказы**
- Каталог: сетка 2×N, поиск в шапке, фильтр, карточка товара по нажатию
- Корзина → экран **Оформление** (телефон, адрес, комментарий, необязательный промокод) → заказ
- Цены в **сомах**
- **Мои заказы** — статусы от склада; в шапке кружок обновления (зелёная точка при новых данных) и меню ≡
- **Поддержка** — из меню профиля; обновление на экране

Зелёная точка появляется, если склад или поддержка что-то изменили (проверка раз в ~30 сек).

## Промокоды

Поле на экране оформления, подставлять не обязательно. После seed на админке:

| Код | Что должно произойти |
|-----|----------------------|
| `ROLA10` | −10% от суммы товаров, один раз на этого клиента |
| `FIRST100` | −200 сом, пока код не исчерпан (первые 100) |

Скидка видна в превью до отправки заказа и в самом заказе. Повторно тот же код тем же аккаунтом не должен пройти.

Новые коды создаёт владелец: сайт → **Промокоды**.

## Push-уведомления

Нужны **оба** ключа Firebase:

1. `mobile/google-services.json` — клиент, чтобы получить FCM-токен.
2. `FIREBASE_SERVICE_ACCOUNT_JSON` в `admin/.env` — сервер, чтобы отправить пуш. После правки `.env` перезапустите админку.

iOS в этой инструкции не покрыт (нужен платный Apple Developer).

### Как проверить пуш

1. Админка запущена, в `.env` валидный сервисный JSON, dev-сервер перезапущен.
2. На телефоне development build, вы вошли как клиент, уведомления разрешены.
3. В терминале админки: `POST /api/customer/push-token` → 200.
4. Оформите заказ — баннер **«Заказ оформлен»**.
5. На сайте владелец/склад подтверждает заказ — **«Заказ подтверждён»**. Отклонение с причиной — **«Заказ отклонён»**.
6. Успех на сервере: `[push] FCM send ok`. Если ключа нет: `[push] FCM-токен есть, но FIREBASE_SERVICE_ACCOUNT_JSON не задан — пропуск`.

Телефон не в спящем режиме без сети; для Xiaomi/HyperOS в настройках приложения включите автозапуск и уведомления канала **Заказы**.

## Как проверить сценарий целиком

1. Админка: migrate, seed, `npm run dev`. Владелец на http://localhost:3000.
2. Приложение: LAN Metro + `EXPO_PUBLIC_API_URL` на IP компьютера. Регистрация клиента.
3. Каталог открывается, товар в корзину, оформление с телефоном и адресом, опционально `ROLA10`.
4. Заказ в **Мои заказы** со статусом ожидания; на сайте тот же заказ.
5. Подтверждение/отклонение на сайте → статус в приложении (обновить или подождать зелёную точку) и пуш на телефон.
6. Профиль: имя и адрес сохраняются после повторного входа.

Автопроверка типов: `npx tsc --noEmit`. Проверки API/промо — `npm run test:bug-catcher` в `shop-admin`.
